# NR-18 — Установка и release candidate

Статус: PLANNED. Фаза: Qualification. Зависимости: [17](NR-17.md).

## Цель

Поставить воспроизводимый артефакт, который устанавливается и откатывается по инструкции.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Создать versioned build/package, checksums и dependency/license inventory; выбрать distribution format без обязательной публикации в registry.
2. Документировать pin upstream, установка runtime, config migration, ChatGPT sign-in/connector setup и uninstall.
3. Проверить macOS arm64 и x64: native live smoke на primary hardware, install/start/doctor на второй архитектуре с конкретным evidence.
4. Подготовить clean-machine install script/checklist, artifact manifest и rollback procedure.

## Контракт и ограничения

Release artifact связан с source SHA и lockfile; версия NightReviewer и bridge pin видимы в doctor/report. Distribution не содержит cookies, credentials, fixture private logs.

## Критерии приёмки

- **NR-18-AC1**: Установка из артефакта на чистом primary macOS даёт offline demo и live submit без редактирования source.
- **NR-18-AC2**: Secondary macOS architecture install/start/doctor проверены; отсутствие оборудования явно BLOCKED для заявленной поддержки.
- **NR-18-AC3**: Upgrade/backup/restore/rollback сохраняют историю либо явно запрещают несовместимый downgrade.
- **NR-18-AC4**: Checksum verified, license notices включены, uninstall оставляет пользовательские данные по умолчанию.

## Проверки и evidence

- Artifact smoke, intentional checksum corruption rejection, clean config/uninstall.
- Reinstall/upgrade на копии persisted fixture database.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

App Store/notarization, SaaS и Windows packaging не обязательны для v1.

## Сбои, риски и откат

Нельзя объявить secondary architecture поддержанной по одному cross-compile. Lead может предложить user-approved сужение target, но не скрыть недостающий gate.

## Поставка

Один bounded PR `[NR-18] Установка и release candidate` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
