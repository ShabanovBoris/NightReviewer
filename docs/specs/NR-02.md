## D70 — isolated browser-only unavailable runner correction

Unavailable mode загружает только loopback base URL и точную модель `chatgpt-web/gpt-5.6-sol`; `BRIDGE_SPIKE_API_KEY` и `BRIDGE_SPIKE_CLIENT_VERSION` для этого режима не требуются. До Responses POST health должен подтвердить `service=codex-chatgpt-web`, version `6.1.3`, `mode=browser-only`, `accepting_turns=true` и нулевые HTTP/browser active-turn counts. Этот путь не обращается к `/v1/models`.

Runner отправляет один свежий synthetic thread/turn/canary с единственным strict `read_fixture` tool definition, без `Authorization`. Он принимает только HTTP 200 `text/event-stream`, содержащий ровно один terminal `response.failed` с `status=424`, `errorType=connector_error`, `code=connector_not_found`; completion, incomplete outcome, function/tool call, возможный fixture/tool output, несовпадающий typed outcome или неполный sanitized trace закрывают проверку как failure. После ожидаемого отказа runner повторно проверяет isolated health: тот же PID/version/browser-only mode и нулевые active-turn counts.

`--connector-unavailable-only` остаётся отдельным явным LIVE режимом. Он отвергает `mode=full` до Responses POST, чтобы нельзя было случайно направить unavailable probe в production runtime. Offline tests используют только injected fake fetch. Они проверяют полный ожидаемый sequence, отсутствие API key/client version, нулевой model-catalog traffic, отсутствие Authorization, неправильные ответы и изменившийся/non-idle post-health. Эти tests не доказывают, что unavailable connector subcheck прошёл LIVE.

Решение Lead D70: `NR-02-AC1=PASS_LIVE_PENDING_INDEPENDENT_REVIEW`, `NR-02-AC2-cancellation=PASS_LIVE_PENDING_INDEPENDENT_REVIEW`, `NR-02-AC2-unavailable=NOT_RUN`, `NR-02-AC2-overall=INCOMPLETE`, `NR-02-AC3=DEFERRED_HARDENING`, `NR-02-AC4=PASS_DOCUMENTATION_ONLY_PENDING_D70_UPDATE`; reviewer approval отсутствует, merge не авторизован. D70 не разрешает production или isolated HTTP, connector/browser action, повтор AC1/cancellation, AC3, DEV, reviewer request или merge. Для следующего live действия требуется отдельное решение Lead.

## D56 — ChatGPT-Web route contract

Каждый будущий AC1 run должен задавать `BRIDGE_SPIKE_MODEL=chatgpt-web/gpt-5.6-sol`. Не выводить slug из выбранной native Codex-модели и не добавлять `chatgpt-web/` произвольно. В upstream `6.1.3` только Web-prefixed slug проходит в ChatGPT-Web browser adapter; unprefixed `gpt-6.1-sol` идёт в native Responses passthrough и не может вызвать configured connector.

Settings loader, preflight/model guard и непосредственная граница Responses request отказывают до fetch при любом другом slug. `/v1/models` обязан содержать точную Web-строку с `high` в `supported_reasoning_levels`; native row не является заменой. В initial request body сохраняются модель, фиксированный `reasoning.effort=high`, единственный strict `read_fixture` tool, прежняя JSON schema и turn metadata. Sanitized D52 ledger записывает точный model slug в settings/catalog stages и не пишет credential.

Offline tests доказывают отказ `gpt-6.1-sol` до первого fetch, принятие точного route slug, catalog guard с `high`, rejection каталога только с native slug, тело simulated Responses запроса и zero real network/connector calls. Эти checks не меняют AC1: она остаётся UNVERIFIED до отдельно разрешённого LIVE round-trip.

## D52 — durable-evidence contract (retained unchanged)

Каждый будущий разрешённый запуск получает стабильный `evidenceRunId` и точный SHA текущего PR head до создания сетевого side effect. Host wrapper отказывается запускаться при неверном Bun `1.4.2`, dirty worktree, другой ветке или head, не совпавшем с `BRIDGE_SPIKE_EXPECTED_PR_HEAD_SHA`.

Runner синхронно записывает и `fsync`-ит каждое событие `_attempted` до соответствующего side effect. Получение HTTP-ответа, завершение stream, tool call, подготовка результата fixture, финальная корреляция и health observation записываются отдельными последующими стадиями. Terminal event содержит классификацию выхода, последний доказанный этап, общее состояние `requestSent` и отдельное состояние первой Responses-попытки. Ошибка транспорта после `_attempted` не считается доказательством получения ответа; неизвестное сохраняется как `UNKNOWN`.

Host wrapper до spawn создаёт и flush-ит закрытую директорию и файлы evidence, `stdout.raw` и `stderr.raw` с правами `0700/0600`. Он запускает только фиксированный Bun `1.4.2` AC1 child, дренирует оба потока без вывода в терминал и сохраняет точные байты частно под игнорируемым `.nightreviewer/`. Sanitized receipt содержит SHA-256 и byte count потоков/журнала, точные UTC start/finish, exact PR head, exit code/signal, terminal classification и allowlisted stage metadata. Он не включает сырые потоки, API key, cookie, prompt, model output, fixture contents или полный tool output.

До выдачи receipt wrapper проверяет run ID/head, UTC timestamps, последовательность, allowlist полей и ровно один terminal event. Для успеха нужна полная ordered последовательность от settings validation до post-AC1 health; пропуск, перестановка, частичная запись, отсутствие terminal event или несовпадение с exit status закрывают run как capture failure. Инъецированные tool-call/transport/fixture/correlation ошибки и simulated success проверяются только через fake fetcher и временное локальное fixture; никакого внешнего HTTP или вызова connector эти tests не выполняют.
