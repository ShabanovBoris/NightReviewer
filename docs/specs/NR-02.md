## Цель и текущий маршрут

Доказать минимальный настоящий ChatGPT Web round-trip на уже работающем production Codex Web GPT `6.1.3`, не останавливая и не перенастраивая runtime или существующий production tunnel.

По source-checked correction Lead D41 production worker выбирает connector по точному `config.appName`. Неизменённый production config выбирает **`Codex Native2`**. Ранее созданный **`Codex Native2 NR-02`** остаётся вспомогательным connector и для этой LIVE проверки не используется. Его имя, permission, authentication и tunnel binding не меняются. Connector selection фиксируется решением Lead по существующему production config; текущий независимый tool callback ещё не наблюдался.

Lead D41 подтверждает для upstream `6.1.3` нужные harness контракты: `/healthz`, аутентифицированный `/v1/models`, `POST /v1/responses` и адресный `/admin/interrupt-turn`. Это source-level основание для ограниченной адаптации runner, не LIVE receipt. Исторический upstream pin `6.1.1` / `a13cd09950969f43e3b7e25c71fa43efaf5446c5` сохраняется только для прежнего source audit и MIT license reference.

## Acceptance criteria

Ровно один разрешённый `read_fixture` вызов, аргумент ровно `{ "fixture": "probe" }`, затем коррелированный `function_call_output`; финальный JSON содержит только этот canary и точный SHA-256 controlled fixture. Health, catalog, preflight, локальные fixtures и модельный текст без callback не являются PASS.
- **NR-02-AC2 — GATING, PARTIALLY AUTHORIZED, NOT_RUN:** разрешена максимум одна cancellation проверка по синтетическим `threadId`/`turnId`: один активный HTTP turn, точный `/admin/interrupt-turn`, HTTP 200, `status=ok`, `cancelled_http_turns=1`, коррелированное завершение stream в течение 10 секунд после acknowledgement и отсутствие `response.completed`. Unavailable-connector/tool часть не авторизована и остаётся `NOT_RUN`; cancellation alone не даёт AC2 PASS.
- **NR-02-AC3 — DEFERRED_HARDENING:** прежняя трёхконтекстная matrix не блокирует minimum-working milestone. Три контекста не запускать по D41; свежий context и уникальный canary остаются обязательными для AC1.
- **NR-02-AC4 — PASS_DOCUMENTATION_ONLY после локальной проверки:** эта спецификация, task, ADR, evidence summary и runbook должны отражать correction D41, границы разрешения и действительные LIVE статусы. Это не PASS для AC1/AC2.

## D41 — ограниченная реализация и порядок запуска

### Phase A: source-checked runner adaptation

Runner использует только точную fail-closed версию `6.1.3`, без диапазона, fallback или env override. Перед live traffic он проверяет service/status/PID/mode/readiness, успешный аутентифицированный model catalog, наличие выбранной модели с `high` effort, стабильность PID/version и успешный учёт catalog запроса. Обе health observations должны показывать `active_http_turns=0` и `active_browser_turns=0`; отсутствующее или ненулевое значение закрывает gate.

Каждое LIVE действие требует отдельного флага. `--live` без одного явного режима завершается до чтения настроек или сетевого запроса. `bridge:live` означает только `--ac1-only`; cancellation доступна только через `bridge:cancel` / `--cancel-only`. Трёхконтекстная реализация сохранена для будущего hardening, но не запускается в D41. `--connector-unavailable-only` по D41 не выполнять.

Phase A выполняет только локальную deterministic проверку. Production preflight и LIVE traffic запрещены до публикации ограниченной адаптации в PR #3 и успешного GitHub CI `verify` на её точном head.

### Phase B: read-only preflight и LIVE

После Phase A и точного CI допускается одна read-only preflight команда — `bun run bridge:preflight`. Её результат должен подтвердить production `6.1.3`, healthy/full/accepting state, idle counts до и после catalog, доступность выбранной модели с high effort, тот же PID и неизменённый production config с `appName=Codex Native2`. Любое несоответствие означает STOP; LIVE остаётся `NOT_RUN`.

Если preflight прошёл, разрешён один `bun run bridge:live` для AC1. Он делает один `runFreshContext`, один canary и один function-call round-trip, печатает только sanitized digest-bound receipt. После AC1 перепроверяется healthy idle state; только затем разрешена одна `bun run bridge:cancel`. При обычном one-shot ChatGPT tool approval prompt пользователь может одобрить только эту операцию. Запрос постоянного разрешения, изменения connector settings или более широких действий означает STOP.

Не останавливать и не перезапускать production/DEV, не менять runtime/config/tunnel/connector/credentials, не запускать setup или Verify, не создавать новый tunnel/key, не использовать `Codex Native2 NR-02`, не выполнять unavailable-tool subcheck и не запускать три контекста. Секреты и содержимое fixture не включать в receipt.
