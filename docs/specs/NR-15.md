# NR-15 — CLI, diagnostics и эксплуатация

Статус: PLANNED. Фаза: Hardening. Зависимости: [14](NR-14.md).

## Цель

Сделать ежедневное использование и поиск причин сбоя понятными без чтения исходников.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. CLI команды setup/doctor/serve/submit/status/fix/cancel/report/backup/restore и version по фактическому API.
2. JSON output для automation, человекочитаемый status/progress/nextAction и стабильные exit codes.
3. Structured local logs/metrics по run/cycle без prompts/secrets по умолчанию; export sanitized support bundle.
4. Runbook: login expiry, bridge/UI drift, rate limits, queue stall, migration, backup, disk pressure и остановка.

## Контракт и ограничения

Предлагаемый exit code contract: 0 успешная команда/approved wait; 2 invalid input; 3 needs_fix при wait; 4 blocked/failed; 130 explicit interrupt. Async submit success = accepted, не approved.

## Критерии приёмки

- **NR-15-AC1**: Новый оператор по README выполняет offline demo и понимает NEEDS_FIX/APPROVED/BLOCKED.
- **NR-15-AC2**: doctor различает process health и реальный connector canary; live smoke явно opt-in.
- **NR-15-AC3**: JSON CLI parser стабилен; stderr не загрязняет stdout.
- **NR-15-AC4**: Support bundle содержит версии/IDs/ошибки и не содержит canary secrets или private source.

## Проверки и evidence

- CLI integration exact exit codes, piping output, Ctrl-C, paths with spaces.
- Runbook exercise восстановления backup в новую папку.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Нет web dashboard и удалённой telemetry без opt-in.

## Сбои, риски и откат

Doctor не чинит пользовательские настройки незаметно. Rollback config через сохранённый backup, owned processes only.

## Поставка

Один bounded PR `[NR-15] CLI, diagnostics и эксплуатация` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
