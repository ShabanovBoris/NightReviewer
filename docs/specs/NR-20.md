# NR-20 — Финальная поставка и приёмка lead

Статус: PLANNED. Фаза: Release. Зависимости: [19](NR-19.md).

## Цель

Завершить проект работающим release на main и явным принятием lead.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Свести acceptance matrix: каждый gate → точный command/run/artifact/PR/SHA и результат.
2. Подготовить release notes, ограничения, operator quickstart, support/recovery и полный демонстрационный сценарий.
3. Провести финальный development reviewer review release PR; закрыть blockers, получить merge authorization и merge.
4. На resulting main SHA собрать/проверить финальный артефакт, доказать code-tree equivalence tested candidate либо повторить затронутые qualification gates.
5. Отправить lead PROJECT_ACCEPTANCE_REQUEST и получить PROJECT_ACCEPTED либо продолжить назначенные corrective PR.

## Контракт и ограничения

Acceptance manifest вне self-referential commit: main SHA, reviewed PRs, artifact checksum, candidate equivalence, all gates, raw receipt refs, unresolved risks. Lead acceptance привязан к hash этого manifest.

## Критерии приёмки

- **NR-20-AC1**: Все NR-01…NR-20 имеют merged PR references; нет required NOT_RUN/BLOCKED gate.
- **NR-20-AC2**: Финальный main/artifact запускается по README и проходит MCP/live full fix demo.
- **NR-20-AC3**: Reviewer blockers пусты; все обязательные checks зелёные на фактическом integration result.
- **NR-20-AC4**: Получен настоящий PROJECT_ACCEPTED от настроенного lead chat с exact main SHA/manifestHash.

## Проверки и evidence

- Release artifact smoke и финальный end-to-end demo; compare tested candidate tree/lockfile/prompts/config с main.
- Проверить ссылки/evidence hashes и ложные claims о выполнении; missing receipt = blocker.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Нельзя объявить completion по собственному заключению implementer или только по merged PR.

## Сбои, риски и откат

Если lead отклонил проект, /goal продолжается с corrective assignment. Если доступа к lead нет — WAITING_EXTERNAL, не SUCCESS. Release rollback описан и проверен без удаления DB.

## Поставка

Один bounded PR `[NR-20] Финальная поставка и приёмка lead` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
