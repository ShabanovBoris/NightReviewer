## Критерии приёмки NR-02

- **NR-02-AC1 — GATING:** Один настоящий LIVE ChatGPT request через production bridge 6.1.3 в новом контексте с уникальным canary; ChatGPT выполняет безвредный контролируемый read_fixture round-trip через Codex Native2 NR-02 и возвращает коррелированный реальный ответ. Health/readiness или contract fixture не являются PASS.
- **NR-02-AC2 — GATING:** Ограниченная ошибка для недоступного connector/tool с наблюдаемой typed ошибкой и cancellation с наблюдаемым acknowledgement и завершением коррелированного stream. Детали cancellation сохраняют ранее зафиксированную D6 границу, если Lead не заменит её новым решением. Обе части требуют LIVE receipts.
- **NR-02-AC3 — DEFERRED_HARDENING:** Полная matrix из трёх fresh contexts и проверка отсутствия межсессионной утечки не блокируют minimum-working milestone. AC1 всё ещё требует свой fresh context и уникальный canary. Предыдущие три-context receipts не предполагаются и не заявляются.
- **NR-02-AC4 — GATING DOCUMENTATION:** Spec/task/ADR/evidence точно различают 6.1.3 production baseline, user-attested transport binding, исторический 6.1.1 source audit, ограничения текущего harness, текущие LIVE статусы и воспроизводимый следующий шаг.

Текущее состояние по evidence: AC1 NOT_RUN, AC2 NOT_RUN, AC3 DEFERRED_HARDENING, AC4 PASS только для документационного критерия после doc audit. Это не означает, что выполнены LIVE критерии или завершён NR-02.
