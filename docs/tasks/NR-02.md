## Требования к durable evidence

1. Устанавливать стабильный `evidenceRunId` и полный точный PR head SHA до любого network-capable этапа. Сохранять `startedAtUtc`, `finishedAtUtc`, terminal classification, точный child exit code и signal.
2. Перед запуском child создать и flush-ить приватную директорию/файлы. На ошибке инициализации storage child spawn запрещён.
3. Для каждого внешнего запроса синхронно persist+fsync `_attempted` до вызова fetch. Отдельно записывать получение HTTP response, завершение stream, observed tool call, fixture attempt/result, continuation, final correlation и post-AC1 health.
4. Не делать вывод, что запрос ушёл, только из исключения. Terminal record обязан содержать furthest `lastProvenStage`, общий `requestSent` и отдельный `initialResponsesRequestSent`, включая `UNKNOWN`.
5. Сохранять приватные точные stdout/stderr bytes child под mode `0600`; директории — `0700`. Публичный receipt содержит лишь hash, byte count и allowlisted metadata. Не сохранять API keys/tokens/cookies, prompts, model free-form output, fixture contents или tool output.
6. В wrapper валидировать schema/run/head, UTC, contiguous sequence, allowed fields, ordered stages, ровно один terminal event и соответствие terminal event process exit. Неполный, испорченный или не совпавший ledger — fail closed.
