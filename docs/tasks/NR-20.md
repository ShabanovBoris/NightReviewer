# Задание агенту: NR-20 — Финальная поставка и приёмка lead

Скопируй этот текст в implementation-сессию после назначения lead. Если выполняется основной GOAL, это payload очередного этапа, а не новая цель вместо проекта.

```text
Ты implementation agent репозитория https://github.com/ShabanovBoris/NightReviewer.
Выполни NR-20: Финальная поставка и приёмка lead.
Конечный результат — проверенный PR, слитый в main, и подтверждённый TASK_COMPLETED для lead.

Прочитай AGENTS.md, docs/STATUS.md, docs/specs/NR-20.md,
docs/DEFINITION_OF_DONE.md и docs/protocols/DEVELOPMENT.md.
Используй действующий session.local и реальное TASK_ASSIGNMENT от lead.
Сначала сверь specHash, current main и завершение зависимостей: NR-19.
Не присваивай себе роль lead/reviewer. Если assignment нет, запроси его;
если готовая реализация уже существует, сначала проверь соответствие ТЗ.

Цель: Завершить проект работающим release на main и явным принятием lead.
Обязательные результаты:
1. Свести acceptance matrix: каждый gate → точный command/run/artifact/PR/SHA и результат.
2. Подготовить release notes, ограничения, operator quickstart, support/recovery и полный демонстрационный сценарий.
3. Провести финальный development reviewer review release PR; закрыть blockers, получить merge authorization и merge.
4. На resulting main SHA собрать/проверить финальный артефакт, доказать code-tree equivalence tested candidate либо повторить затронутые qualification gates.
5. Отправить lead PROJECT_ACCEPTANCE_REQUEST и получить PROJECT_ACCEPTED либо продолжить назначенные corrective PR.

Покрой evidence критерии NR-20-AC1…NR-20-AC4.
Граница: Нельзя объявить completion по собственному заключению implementer или только по merged PR.
Существенный риск: Если lead отклонил проект, /goal продолжается с corrective assignment. Если доступа к lead нет — WAITING_EXTERNAL, не SUCCESS. Release rollback описан и проверен без удаления DB.

Работай в feature branch от актуального main. Реализуй минимальное целостное
решение и требуемые проверки. Зафиксируй реальные команды/exit codes,
артефакты, ограничения, observed versions. Не выдавай NOT_RUN за PASS.
Commit + push branch, затем создай PR с base=main и таблицей AC → evidence.
Отправь REVIEW_REQUEST в настроенный reviewer chat для точных base/head SHA.
Сохрани raw response. Исправь blockers и запроси FIX_REVIEW_REQUEST для нового SHA.
После 3 неудачных rounds или scope conflict передай решение lead.
После reviewer APPROVED запроси у lead MERGE_AUTHORIZED на тот же tuple.
Перепроверь GitHub checks/base/head; при изменении обнови approvals.
Слей PR без обхода правил, проверь merged state/main CI и отправь lead
TASK_COMPLETED с PR URL, merge/main SHA, acceptance/evidence и остаточными рисками.

Не завершай задачу на стадии локального кода, commit, push или открытого PR.
При реальном внешнем блокере сохрани checkpoint и сообщи точное действие
для разблокировки; не имитируй approval и не обходи ограничение.
```
