# NR-10 — Tunnel и production context MCP

Статус: PLANNED. Фаза: Web MVP. Зависимости: [06](NR-06.md), [09](NR-09.md).

## Цель

Подключить реальные ChatGPT reviewers к ограниченному контексту через tunnel без полного terminal harness.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Реализовать production tool loop/binding adapter и отдельную connector identity согласно NR-02 ADR.
2. Один управляемый tunnel runtime, индивидуальные capability bindings для turns; health/reconnect/revoke.
3. Setup/doctor проверяют реальный read_file canary через ChatGPT connector, а не только TCP health.
4. Документировать login/connector steps, secrets storage и ownership; повтор setup не меняет чужую Codex конфигурацию.

## Контракт и ограничения

Connector предоставляет только review_context tools. Prompt инструкции не являются access control; ограничения исполняет сервер.

## Критерии приёмки

- **NR-10-AC1**: Live reviewer читает pinned fixture через tunnel и цитирует фактический код.
- **NR-10-AC2**: Два concurrent live turns не обмениваются контекстом, подмена run binding отвергается.
- **NR-10-AC3**: Disconnect/reconnect/cancel не оживляют отозванный токен и не выполняют чужой запрос.
- **NR-10-AC4**: Setup/uninstall затрагивают только NightReviewer-owned config; секреты отсутствуют в Git/log/artifacts.

## Проверки и evidence

- Live end-to-end canary, stale/replayed capability, tunnel unavailable.
- Automated ACL contract через транспорт, redaction tests для error path.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Никаких команд изменения кода или unrestricted native tool registry.

## Сбои, риски и откат

Недоступный Developer Mode/connector — AUTH_REQUIRED/BLOCKED и инструкция оператору. Не обходить workspace restrictions; revoke перед uninstall.

## Поставка

Один bounded PR `[NR-10] Tunnel и production context MCP` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
