# NR-04 — SQLite и неизменяемые артефакты

Статус: PLANNED. Фаза: Core. Зависимости: [03](NR-03.md).

## Цель

Сохранять историю, raw output и переходы атомарно, с возможностью восстановления.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Создать versioned migrations и таблицы ARCHITECTURE.md с FK/unique/check constraints.
2. Добавить транзакционный repository API для create/transition/attempt/result/fix/cancel и outbox.
3. Raw artifacts записывать атомарно с SHA-256 до parsing; journal сохраняет rejected/malformed/obsolete результаты.
4. Добавить owned storage dir permissions, backup/restore и reconciliation orphan files/missing artifact references.

## Контракт и ограничения

Store API принимает expectedVersion/fencingToken; version conflict не overwrite. Idempotency keys scoped by caller/operation и нормализованный request hash.

## Критерии приёмки

- **NR-04-AC1**: Restart сохраняет reviews, findings, provenance и последние committed states.
- **NR-04-AC2**: Два submit с одним key создают один review; другой payload даёт CONFLICT.
- **NR-04-AC3**: Crash между artifact write/DB commit не приводит к успешному missing result; reconciliation обнаруживает расхождение.
- **NR-04-AC4**: Backup восстанавливается в новую папку и проверяет hashes; миграция не теряет записи.

## Проверки и evidence

- Real temporary SQLite tests: concurrent writers, rollback, FK, duplicate ingest.
- Kill/fault injection на boundary transaction; malformed raw bytes сохраняются.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Без semantics aggregation и запуска браузера.

## Сбои, риски и откат

До миграции backup; downgrade неподдерживаемой schema запрещён. Не удалять raw для удобства cleanup; retention только отдельным явным действием.

Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
