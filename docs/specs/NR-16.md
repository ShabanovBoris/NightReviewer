# NR-16 — Проверка изоляции и защитных границ

Статус: PLANNED. Фаза: Hardening. Зависимости: [15](NR-15.md).

## Цель

Проверить, что недоверенный код и ответы моделей не могут расширить доступ или подделать approval.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Описать threat model: malicious repo/prompt injection, forged binding/result, local token leak, cross-review access, oversized output.
2. Проверить все tools/paths/capabilities и result ingest against manifest/attempt/fencing.
3. Добавить malicious fixtures: instructions в README/code, symlink chain, unicode paths, secret canaries и stale artifacts.
4. Закрыть подтверждённые уязвимости; сохранить negative-test matrix и ограничение trusted local user boundary.

## Контракт и ограничения

Обработка repo text как данных, серверные ACL и exact result validation. Prompt фраза read-only не является доказательством изоляции.

## Критерии приёмки

- **NR-16-AC1**: Каждый context tool проходит negative ACL/path tests и не раскрывает secret canary.
- **NR-16-AC2**: Forged/stale/other-SHA result никогда не влияет на verdict.
- **NR-16-AC3**: Prompt injection не предоставляет tools/права и не меняет назначенную policy; невозможность гарантировать semantic immunity описана честно.
- **NR-16-AC4**: Логи, diagnostics, config templates и публичные artifacts проходят secret/redaction checks.

## Проверки и evidence

- Adversarial automated corpus и live controlled injection canary без настоящих секретов.
- Boundary tests network listener auth, origin/token policy если применимо.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не объявлять formal security proof и не выполнять атаки на сторонние сервисы.

## Сбои, риски и откат

Найденный isolation/false-approval bug блокирует release независимо от severity label; remediation в текущем scope либо lead-approved corrective PR.

## Поставка

Один bounded PR `[NR-16] Проверка изоляции и защитных границ` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
