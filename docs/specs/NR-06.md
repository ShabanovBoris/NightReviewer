# NR-06 — Ограниченный read-only review context

Статус: PLANNED. Фаза: Core. Зависимости: [05](NR-05.md).

## Цель

Дать reviewer достаточно кода для анализа без доступа к рабочей машине и чужим runs.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Реализовать manifest/diff/read_file/search/list_files/test_results поверх pinned snapshot.
2. Добавить run-bound capability store, expiry/revocation и role ACL для reviewer/adjudicator/verifier.
3. Ограничить output bytes, pagination, request time, path size; возвращать explicit truncation и cursor.
4. Test result ingestion проверяет SHA/artifact identity и сообщает producer/trust, не приписывая сервису чужое выполнение.

## Контракт и ограничения

Ни один tool не принимает произвольный repo/SHA; base/head side только внутри binding. Search literal по умолчанию. Capability secrets не попадают в diagnostics и публичные evidence.

## Критерии приёмки

- **NR-06-AC1**: Параллельные run A/B не могут прочитать чужие snapshots или reports.
- **NR-06-AC2**: Expired/revoked/forged capability отвергается на каждом методе.
- **NR-06-AC3**: Pagination даёт полный воспроизводимый результат без тихого пропуска.
- **NR-06-AC4**: Bounds/UTF-8/binary/invalid path отвечают typed errors и не зависают.

## Проверки и evidence

- ACL matrix по всем tools; negative path/capability tests.
- Read base deleted file vs head missing file; truncate/search pagination; stale test report.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Без tunnel deployment и unrestricted run_readonly_check/terminal.

## Сбои, риски и откат

При сомнительном binding отказ, не fallback в working directory. Rollback отзывает capabilities перед остановкой context server.

## Поставка

Один bounded PR `[NR-06] Ограниченный read-only review context` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
