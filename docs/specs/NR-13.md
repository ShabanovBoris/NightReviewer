# NR-13 — Fix verification и точный approval gate

Статус: PLANNED. Фаза: V1. Зависимости: [12](NR-12.md).

## Цель

Завершить полный цикл исправлений без переноса approval на непроверенный commit.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Реализовать submit_fix CAS по previous SHA, resolution mapping и новый pinned snapshot.
2. Dispatch всех direction verifiers: их findings плюс прямой fix diff; stable IDs и regression links.
3. Добавить FIXED/NOT_FIXED/REGRESSION/UNCERTAIN, scoped review и policy escalation к новому cycle.
4. Approval record bound к exact head/manifest/policy; CLI/MCP возвращают критерий, а не расплывчатый общий статус.

## Контракт и ограничения

Изменившийся SHA требует verification. Fix attempts не заменяют raw initial review. Крупное изменение scope создаёт REQUIRES_FRESH_REVIEW с причиной и parent link.

## Критерии приёмки

- **NR-13-AC1**: Seeded bug даёт NEEDS_FIX; реальное исправление проходит APPROVED на новом SHA.
- **NR-13-AC2**: Неверное исправление и прямой regression остаются blockers.
- **NR-13-AC3**: Параллельные submit_fix/cancel и stale previous дают один корректный переход.
- **NR-13-AC4**: Scope expansion/uncertainty/недостающий direction не дают approval и требуют явного следующего действия.

## Проверки и evidence

- Integration fixture commits A→bug B→fixed C→regressed D и history rewrite.
- Live полный цикл с оригинальными canonical IDs и raw verification receipts.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не выполнять полный девятикратный review для каждого маленького fix; fresh cycle только с причиной.

## Сбои, риски и откат

После трёх неудачных fix iterations вернуть PAUSED с reason ACTION_REQUIRED, не бесконечный loop. Rollback API не переводит незавершённую проверку в APPROVED.

## Поставка

Один bounded PR `[NR-13] Fix verification и точный approval gate` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
