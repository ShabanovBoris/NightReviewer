# NR-19 — Live soak и стабильность

Статус: PLANNED. Фаза: Qualification. Зависимости: [18](NR-18.md).

## Цель

Подтвердить устойчивый полный workflow на реальном ChatGPT backend и release candidate.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Выполнить 30 последовательных end-to-end review cycles на одном candidate, минимум 3 сессии в течение ≥24 часов.
2. Минимум 10 циклов включают NEEDS_FIX→fix→APPROVED; минимум 5 используют strict 3×3; остальные минимум 3 replica + adjudication.
3. В каждом цикле проверить IDs/SHA/provenance, terminal outcome, resource cleanup и время; учитывать все начатые runs.
4. Добавить controlled cancellation/restart/tunnel interruption отдельно от 30 normal cycles; классифицировать external outage vs app failure.

## Контракт и ограничения

Soak manifest append-only: candidate SHA/artifact/prompt/model/bridge hashes, run ID, started/finished, attempts, outcomes, evidence. Паузы по внешним лимитам сохраняются, не маскируются сбросом счётчиков.

## Критерии приёмки

- **NR-19-AC1**: 30/30 normal cycles достигают корректного ожидаемого terminal outcome без ручного исправления state/rebinding/retry от оператора.
- **NR-19-AC2**: Ноль false approvals, cross-session mixups, потерь acknowledged raw и orphan active resources.
- **NR-19-AC3**: Для малых fixtures ≤500 changed lines p95 normal cycle ≤20 минут при отсутствии external limit; total/tail delays показаны отдельно.
- **NR-19-AC4**: Каждый injected fault имеет корректное recovery/blocked outcome, понятный nextAction и не считается normal success.

## Проверки и evidence

- Live timed 30-cycle harness, memory/disk/leases before-after и diagnosis отчёт.
- Повтор только затронутых deterministic tests после diagnosis; если code/prompt/bridge менялся, новый qualification candidate и новая 30-cycle серия.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не обходить account rate limits и не заменять live soak fake backend.

## Сбои, риски и откат

При внешнем лимите pause и продолжение после разрешённого reset; при дефекте кандидат fail и corrective PR. Вся неуспешная серия остаётся в отчёте.

## Поставка

Один bounded PR `[NR-19] Live soak и стабильность` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
