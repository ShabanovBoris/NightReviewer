# NR-12 — Direction adjudication и canonical findings

Статус: PLANNED. Фаза: V1. Зависимости: [11](NR-11.md).

## Цель

Превратить raw reports в проверенные findings с полной трассировкой решений.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Добавить отдельный adjudicator turn на направление с read-only snapshot и всеми его raw findings.
2. Реализовать output schemas с disposition каждого candidate, canonical IDs, sources и validation rationale.
3. Semantic dedup только при доказанной одной причине; отдельные проблемы в одной строке не объединять механически.
4. Root проверяет полноту disposition/provenance и approval policy; межнаправленные дубли link-овать без потери владельцев.

## Контракт и ограничения

Один reviewer может оказаться прав: голосование не фильтр истины. Каждый candidate → CONFIRMED/REJECTED/UNCERTAIN и evidence. Новые unsupported claims adjudicator не добавляет как confirmed.

## Критерии приёмки

- **NR-12-AC1**: Fixture A/A′/B/C превращается в ожидаемые группы и все исходные references сохранены.
- **NR-12-AC2**: Singleton confirmed bug остаётся blocker, false positive rejected с rationale.
- **NR-12-AC3**: Missing source, invented reference или uncertain candidate блокирует APPROVED.
- **NR-12-AC4**: Strict review завершается 9 replica + 3 adjudication results при общем limit 3.

## Проверки и evidence

- Fake adversarial outputs: dropped finding, duplicate IDs, bad provenance, conflicting evidence.
- Live seeded defect fixture с проверкой canonical result по известному reproducer.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не решать semantic duplicates одним embedding threshold; не делать fresh full review в adjudicator.

## Сбои, риски и откат

Если adjudicator недоступен, state PAUSED/FAILED, не fallback на raw majority. Rollback сохраняет raw и версии adjudication для повторной обработки новым cycle.

## Поставка

Один bounded PR `[NR-12] Direction adjudication и canonical findings` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
