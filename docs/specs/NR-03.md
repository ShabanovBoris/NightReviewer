# NR-03 — Версионированные схемы и машина состояний

Статус: PLANNED. Фаза: Foundation. Зависимости: [01](NR-01.md), [02](NR-02.md).

## Цель

Закрепить исполняемые контракты, которыми пользуются MCP, storage и backend.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Реализовать JSON Schema и TS types для runtime protocol, findings, canonicalization, fix, errors и config.
2. Реализовать pure transition reducer/state guards из RUNTIME.md, включая cancellation, pause и свежий cycle.
3. Определить normalized idempotency payload, full SHA validation (поддерживаемый Git object format), canonical serialization/hash.
4. Описать default strict policy, quotas/deadlines/retry budgets и schema evolution правила; экспортировать валидные/невалидные examples.

## Контракт и ограничения

src/protocol — один источник схем; TS и JSON validation не должны расходиться. Запрет неизвестных enum/полей там, где они влияют на authority; nullable/optional выражены явно.

## Критерии приёмки

- **NR-03-AC1**: Все examples валидируются реальными схемами; invalid fixtures отвергаются с path ошибки.
- **NR-03-AC2**: APPROVED нельзя получить из failed/missing/uncertain результата.
- **NR-03-AC3**: Для каждой state transition проверены допустимые и запрещённые переходы.
- **NR-03-AC4**: Version/hash фиксируют schema, prompt и policy; изменение входного payload под тем же key обнаруживается.

## Проверки и evidence

- Table-driven transitions, conflicting fix/cancel states, malformed finding без evidence.
- Проверить empty vs incomplete review, unsupported schema version и canonical hash order.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Без SQLite, сетевых запросов и LLM semantic decisions.

## Сбои, риски и откат

Schema breaking change требует version bump и ADR. Rollback до использования persisted v1 безопасен; после — только миграционный путь.

## Поставка

Один bounded PR `[NR-03] Версионированные схемы и машина состояний` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
