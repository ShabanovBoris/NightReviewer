# NR-07 — Daemon и внешний MCP lifecycle

Статус: PLANNED. Фаза: Core. Зависимости: [04](NR-04.md), [05](NR-05.md), [06](NR-06.md).

## Цель

Предоставить implementer стабильные submit/status/fix/cancel tools и фоновую работу, независимую от жизни MCP клиента.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Создать single-owner local daemon и authenticated local RPC; stdio MCP — тонкий клиент.
2. Реализовать runtime tools, validation, idempotency, paged status/events и nextAction.
3. Submit транзакционно регистрирует job, возвращает ID; snapshot/processing выполняются async.
4. Пока fix backend не реализован, запрос не должен выдавать фиктивный успех: вернуть явную capability/state ошибку с сохранением доступных полей контракта.

## Контракт и ограничения

Локальный listener loopback/Unix socket; lifecycle token не в argv/log. MCP stdout содержит только protocol, diagnostics — stderr. Отключение stdio клиента не отменяет durable job.

## Критерии приёмки

- **NR-07-AC1**: Реальный MCP client выполняет submit/status/cancel; повтор submit возвращает тот же ID.
- **NR-07-AC2**: Закрытие MCP клиента и подключение нового сохраняет review ID/state.
- **NR-07-AC3**: Unauthorized RPC/unknown repo/stale fix дают правильные ошибки.
- **NR-07-AC4**: Одновременно два daemon не владеют одной queue; shutdown/drain не теряет accepted jobs.

## Проверки и evidence

- Integration MCP handshake/list_tools/call_tool и malformed inputs.
- Daemon ownership, client disconnect, queued cancel и shutdown while work pending.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Нет live browser и автоматического GitHub merge.

## Сбои, риски и откат

Версия daemon/RPC проверяется handshake; mismatch fail closed. Rollback останавливает только owned daemon после drain.

## Поставка

Один bounded PR `[NR-07] Daemon и внешний MCP lifecycle` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
