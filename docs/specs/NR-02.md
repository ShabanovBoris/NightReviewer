# NR-02 — Технический spike ChatGPT Web backend

Статус: PLANNED. Фаза: Foundation. Зависимости: [01](NR-01.md).

## Цель

Доказать минимальный реальный transport contract, прежде чем строить систему вокруг недоказанных предположений.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Прочитать source закреплённого upstream: Responses request/response, outer tool loop, task identity, cancellation, health/model discovery.
2. Создать изолированный spikes/bridge harness: один fresh chat, structured output и один безвредный read-only tool round-trip.
3. Зафиксировать реально потребовавшиеся поля/headers/SSE events, ownership процесса/tunnel и правила завершения.
4. Проверить три независимых контекста с уникальными canary IDs и отсутствие смешивания; это диагностический spike, не production scheduler.
5. Выбрать transport ADR: local Responses плюс outer driver либо минимальный adapter patch; сохранить pin и законченную инструкцию запуска.

## Контракт и ограничения

Артефакт docs/decisions/0002-bridge-contract.md + runnable spike + sanitized live receipts. Нельзя считать DEV simulated=true за настоящий callback.

## Критерии приёмки

- **NR-02-AC1**: Реальный ChatGPT ответ связан с исходным run/canary; tool читает контролируемую fixture.
- **NR-02-AC2**: Один тест cancellation и один недоступный connector дают наблюдаемый typed outcome.
- **NR-02-AC3**: Три fresh sessions не видят canaries соседей; identities/cleanup доказаны receipts.
- **NR-02-AC4**: ADR перечисляет supported/unsupported возможности, выбранный pin, dependency license и воспроизводимый следующий шаг.

## Проверки и evidence

- Live macOS smoke с реальным аккаунтом; сохранить timing/observed model и raw sanitized trace.
- Contract fixtures для observed SSE happy/error/partial completion.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не строить полный orchestrator и не считать spike релизным backend.

## Сбои, риски и откат

Отсутствующий аккаунт/connector — BLOCKED. Backend bridge incompatibility разрешается с lead; не заменять Web API провайдером ради PASS. Rollback удаляет только owned spike runtime.

## Поставка

Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
