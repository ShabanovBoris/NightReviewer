# NR-01 — Основа проекта и рабочий процесс

Статус: PLANNED. Фаза: Foundation. Зависимости: нет; требуется READY lead/reviewer.

## Цель

Получить воспроизводимый TypeScript-проект и доказать development loop lead → implementation → reviewer → merge.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Подтвердить ADR-0001 с lead; закрепить runtime/package manager, target platforms и lockfile.
2. Создать минимальные src/tests, strict typecheck, lint, test, build и единый verify; не писать пустые тесты ради зелёного CI.
3. Настроить CI на pull_request и main с минимальными permissions; contributor guide и PR template с task/criteria/evidence.
4. Проверить READY от обоих чатов и документировать локальную конфигурацию; для branch protection описать требуемые checks и проверить доступные настройки без обхода правил.

## Контракт и ограничения

Команды bun install --frozen-lockfile и bun run verify должны существовать после этой задачи. verify включает реальные typecheck/lint/test/build; docs-only проверки входят при необходимости.

## Критерии приёмки

- **NR-01-AC1**: Чистая установка и verify завершаются с exit 0 на macOS и Linux CI.
- **NR-01-AC2**: Намеренно сломанный typecheck/test делает CI красным, после отката зелёным.
- **NR-01-AC3**: Repo не содержит credentials/session.local; sample config валидируется и отвергает одинаковые lead/reviewer URL.
- **NR-01-AC4**: Первый implementation PR прошёл реальный reviewer и lead по nr-dev/1, merge подтверждён GitHub.

## Проверки и evidence

- Smoke минимального CLI/version или pure core module; не тестировать заглушку true.
- Проверка отсутствующего env/config даёт понятную ошибку, без секретов.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Нет daemon, browser integration или продуктовой approval логики.

## Сбои, риски и откат

Если выбранный runtime недоступен, lead принимает ADR; не заменять версию незаметно. Rollback — revert PR без удаления пользовательской конфигурации.

## Поставка

Один bounded PR `[NR-01] Основа проекта и рабочий процесс` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
