# NR-14 — Crash recovery, cancellation и пределы ресурсов

Статус: PLANNED. Фаза: Hardening. Зависимости: [13](NR-13.md).

## Цель

Доказать устойчивость к реальным сбоям daemon, tunnel, браузера и хранилища.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Усилить recovery journal/lease reconciliation на всех boundaries: send/accepted/raw saved/parsed/committed.
2. Реализовать graceful drain, forced cancellation fencing, terminal invariants и safe resume.
3. Ввести queue/storage/prompt/time quotas, disk-full handling, retention diagnostics и явный cleanup inactive artifacts.
4. Задокументировать retry matrix: auth/policy fail, rate limit pause до reset/оператора, transient bounded backoff, ambiguous send reconciliation.

## Контракт и ограничения

Не обещать exactly-once Send; обещать отсутствие двойного принятия результата и обнаружение неопределённости. UI human action не воспроизводить автоматически после unknown outcome.

## Критерии приёмки

- **NR-14-AC1**: Crash injection на каждом boundary сохраняет все acknowledged raw outputs и корректное состояние.
- **NR-14-AC2**: Cancel during queued/running/aggregating/verifying гарантированно не допускает позднего APPROVED.
- **NR-14-AC3**: Disk full/DB busy/tunnel drop/browser crash возвращают diagnostics без corrupt success.
- **NR-14-AC4**: После 50 offline fault scenarios нет orphan active leases, duplicate selected outputs или unbounded growth.

## Проверки и evidence

- Process kill/restart integration, 50 cases с seed/trace, bounded retry timing.
- Live один controlled daemon/tunnel interruption с восстановлением/явной reconciliation.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не вводить distributed cluster или multi-host coordinator.

## Сбои, риски и откат

Fault tests только в isolated profile/fixtures. Перед destructive cleanup backup; нельзя терять raw history для получения green metrics.

## Поставка

Один bounded PR `[NR-14] Crash recovery, cancellation и пределы ресурсов` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
