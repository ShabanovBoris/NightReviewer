# NR-05 — Git snapshots и review manifest

Статус: PLANNED. Фаза: Core. Зависимости: [03](NR-03.md), [04](NR-04.md).

## Цель

Отделить проверяемый commit от mutable working tree и сохранить его после GC/удаления source repo.

## Входы и границы

Читать [PRODUCT](../PRODUCT.md), [ARCHITECTURE](../ARCHITECTURE.md), [runtime protocol](../protocols/RUNTIME.md), [development protocol](../protocols/DEVELOPMENT.md) и [DoD](../DEFINITION_OF_DONE.md). Входы: current main SHA, подтверждённое lead назначение, merged evidence зависимостей, spec hash. Если реализация уже частично существует, сначала проверить её и закрывать разницу с ТЗ, а не переписывать.

## Работы

1. Resolve repoId из allowlist; resolve base/head в полные commits, проверить наличие и ancestry policy.
2. Создать owned object snapshot/pinned refs или bundle с base/head trees; сгенерировать content-addressed manifest/diff.
3. Поддержать renamed/deleted/new files, binary/LFS/submodule metadata, changed paths и limits.
4. Git выполнять argv-вызовами без shell interpolation и external diff/textconv/hooks; reads по objects, не symlink targets.

## Контракт и ограничения

Manifest: repo identity, base/head, merge-base/diff policy, paths/blob hashes, task/criteria hashes, exclusions/coverage, createdAt. Base→head tree diff — явно выбранная семантика.

## Критерии приёмки

- **NR-05-AC1**: Изменения working tree после submit не меняют read_file/diff.
- **NR-05-AC2**: Удаление/GC исходного repo не ломает уже принятое review.
- **NR-05-AC3**: Symlink, ../, option-like revision/path и submodule не дают чтение вне snapshot.
- **NR-05-AC4**: Большой/binary/missing LFS контент явно отмечен; coverage gap не может стать APPROVED.

## Проверки и evidence

- Fixture repo с rename/delete/binary/symlink, spaces/unicode paths.
- Repository mutation during snapshot, invalid/unreachable commit и bounds.
- Приложить команды, exit codes, environment/версии, exact SHA и hashes артефактов. Live-проверки отмечать LIVE, deterministic FAKE/CONTRACT; не подменять одно другим.
- Связать каждый AC с доказательством в PR. Общие проверки — только существующие команды из package scripts; после NR-01 обязательно `bun run verify`.

## Не входит

Не запускать build/tests/hooks target repo; worktree не считается security boundary.

## Сбои, риски и откат

Snapshot failure переводит цикл в FAILED до scheduling. Rollback удаляет только owned snapshots с отсутствующими active references.

## Поставка

Один bounded PR `[NR-05] Git snapshots и review manifest` в `main`, включающий код, релевантные тесты, документацию поведения/миграции и evidence index. Пройти reviewer → fix verification → lead merge authorization по точным SHA. После merge проверить resulting main и отправить TASK_COMPLETED. Если lead разбивает задачу, все child PR проходят тот же цикл, родитель завершается только после всех AC. Открытый PR не означает выполненное ТЗ.
